# AML benchmark 审查问题修复记录（2026-10-23）

对应审查中的第 1、3、4、6 项。规范依据：[AML API Guide](https://agentmemories.ai/api-guide)。

## 改动范围

1. **让记忆程序读不到评测答案。** 标准 runner、可续跑 queue、原生方法 bridge 都通过 Linux bubblewrap 启动 worker。只挂载冻结代码、Python 环境、当前历史和问题、当前历史的存储与续跑目录；不挂载 prepared、原始数据集、其他任务结果或主机 home。历史和问题先复制到任务输入目录。使用独立 PID 命名空间，去掉能力、清空继承环境；缺少 bubblewrap 或内核不支持时失败，不退回无隔离执行。返回给协调器的 report/retrieval 文件不能是符号链接或硬链接。

2. **把漏掉的原生配置纳入版本。** 原来的 Python 哈希扩展到 `.env.example`、JSON/TOML/YAML/INI/CFG 等非秘密配置和文本资源，生成 `frozen_native` 副本，并以只读方式挂载给 worker。记录非秘密 provider 参数、Python 可执行文件及已安装包版本的指纹。续跑和新 worker 启动前检查漂移。AMI 原有配置加载逻辑读取冻结的模板；MAX_TOKENS 等预算参与校验，密钥轮换不视作算法参数变化。

3. **阻止凭据再次进入 Git。** 从当前 Git 索引删除 `.env`，保留本地文件并设置权限 `600`。新增 `scripts/check_credentials.py` 和 `.githooks/pre-commit`；本地已启用 hook。检查暂存内容及当前/历史 `.env` 中的密钥值，只报告路径和错误类型，不输出密钥。发布仍使用允许列表导出，并对照当前和历史密钥检查导出内容，不携带 Git 历史。

4. **为记忆 HTTP 接口实现有界重试。** Add 和 Search 使用各自的 AML 状态码集合；网络错误也可重试。每次请求先固定序列化字节，重试保持 ID 和请求体一致。最多 32 次；指数退避上限 60 秒。429 遵循有效 Retry-After（最多 60 秒），缺失/无效时等待 60 秒。永久错误及格式错误立即失败。SDK 的 HTTP 转发后端默认单次上游调用，交给评测端负责重试，避免两层 32 次放大；模型请求的重试逻辑保持原样。

## 适用范围和未完成的外部动作

- 当前五 seed 实验继续使用已冻结代码，没有中断、重启或替换代码。这些修复用于新准备的实验；历史结果不因此自动获得新的隔离保证。
- 安装 `bubblewrap` 后才能运行新的 worker，且需要 Linux 用户/PID 命名空间。可用 `python -m unittest discover -s tests -p test_security.py -v` 检查部署环境。
- 此隔离限定本地文件读取。方法代码、Python 环境和模型资源仍需可信；模型请求所需网络继续开放。它不等于为任意恶意程序提供完整的网络隔离服务。
- 非代码运行资源应位于被冻结并记录的 native 目录中。环境指纹检查包版本，不是整个虚拟环境二进制镜像的逐字节证明。
- **历史 Git 提交仍包含旧密钥，尚未撤销/轮换。** 本地取消跟踪不能让历史密钥失效；需要凭据服务商提供的新密钥。没有改写或强推旧仓库历史，也没有提前使当前实验失去调用权限。公开发布仓库的允许列表导出不包含真实 `.env` 和旧 Git 历史。
- 第 2、5 项不在本次授权修复范围内。
